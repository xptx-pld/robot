# 真机接入前必须确认的问题（G1–G6）

> 这些答案不能从 322 轮元数据推断。规格书第 5.9 节明确要求不得臆造。下列问题
> 按对架构和上线风险的影响排序。每个问题后都注明“若答案不同”的影响。

| 优先级 | 编号 | 问题 | 若答案不同的影响 |
|---|---|---|---|
| P0 | G1 | 机器人具体是什么形态：差速轮式、全向轮、舵机云台、机械臂、无人机还是其他？主控是 MCU、树莓派、ESP32 还是工控机？ | 当前差速轮运动学只适用于两轮差速底盘。其他形态需要替换 `kinematics.py` 与设备协议，CLI 场景也要重写。 |
| P0 | G2 | 上位机到机器人之间的物理链路是什么：USB 串口、CAN、TCP、UDP、MQTT、ROS 1/2 topic、蓝牙还是私有无线？若是串口，波特率、数据位、停止位、校验位是什么？ | 决定 `hal` 适配器与 codec。当前 `PlaceholderJsonCodec` 必须整体替换，否则真机不会响应。 |
| P0 | G2 | 协议帧结构是什么？有无帧头、长度、序号、CRC/校验、应答、心跳、指令超时？速度单位是 m/s、RPM 还是 PWM？ | 决定 `framing.py` 与 `protocol.py`。若采用 PWM 或 RPM，需要增加标定与闭环，不能直接把 `Velocity` 写进现有 JSON。 |
| P0 | G6 | 硬件急停是否独立于上位机？断电/断网/进程崩溃时驱动器是否自动停车？供电电压、峰值电流、保险与接地如何？ | 决定软件看门狗是否足够。若没有硬件急停，不能进行真机运动测试。 |
| P0 | G1/G6 | 最大线速度、角速度、轮径、轮距、减速比、编码器分辨率、电机方向如何定义？ | 当前 `config/robot.example.toml` 中数值全部是示例。错误标定会导致速度与转向错误。 |
| P1 | G3 | 最初要实现的具体行为是什么：遥控、航点、巡线、避障、抓取、语音还是定时动作序列？成功标准是什么？ | 当前只实现“按航点移动”的最小行为。若原项目是巡线或机械臂动作，业务层需要根据真实需求重建。 |
| P1 | G4 | 目标运行平台和 Python 版本是什么？是否需要 ROS/ROS2、Docker、systemd 或 Windows 服务？ | 影响部署、依赖锁定和进程守护。目前仅要求 Python 3.11+，不依赖 ROS。 |
| P1 | G5 | 原来是否使用 Gazebo、CoppeliaSim、Webots 或自建 mock？是否有 URDF、地图、标定文件？ | 若有现成仿真资源，应优先导入；否则当前确定性仿真器用于逻辑验证。 |
| P1 | G6 | 是否有障碍物、坡度、载重、机械限位、碰撞风险？任务中是否允许原地转向？ | 决定是否需要避障、速度包络、姿态保护和更复杂的状态机。 |
| P2 | G2/G6 | 遥控失联、遥测超时、坏帧、急停、故障恢复各自的期望行为是什么？谁负责清除故障？ | 当前实现选择“超时停车、故障锁存、人工显式清除”。若现场要求自动恢复，需要另行评审安全风险。 |
| P2 | G1 | 是否有轮速/IMU/里程计反馈？坐标系与正方向如何定义？ | 当前航点控制假定里程计位姿可用且 x 向前、y 向左、角度逆时针为正。无反馈时只能开环，精度不可保证。 |
| P2 | G4 | 是否需要日志、远程监控、配置热更新、OTA 或数据回传？ | 当前只有进程内健康统计，没有持久化遥测日志。 |

## 建议的第一次人工确认（按顺序）

1. 发一张机器人照片和主控/驱动器照片。
2. 问清电脑到机器人的连接线：USB、网线、CAN 适配器还是无线？
3. 让对方提供旧项目的一份通信样例（十六进制发送与接收）。
4. 确认硬件急停和供电保护是否已经存在。
5. 确认最小成功动作：前进 10 cm、原地转 90°、停车。

在以上问题确认前，项目只应运行仿真；串口模式应架空车轮并使用独立物理急停。
