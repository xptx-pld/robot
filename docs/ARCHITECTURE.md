# 架构说明

## 目标与证据边界

本项目按 `recovery/机器人项目_重建规格书.md` 第 5 节重建。已有材料能证明原始项目
使用 Agent 辅助开发、规模约 1500–3000 行、主要卡点是硬件控制链路，但**不能证明**
原始硬件型号、协议或业务动作。因此本实现把“未知硬件”隔离为可替换的设备层，并以
仿真器验证控制逻辑。

依据：

- 原始源码不可恢复：规格书第 0.2、4 节。
- 架构应采用分层的设备抽象：任务包第 6 节第 2 项。
- 必须提供 mock/fake 设备：任务包第 6 节第 2 项、第七节。
- 不得臆造 G1–G6：规格书第 5.9 节、任务包第七节。

## 分层

```text
CLI / mission
    |
WaypointController       业务行为：目标位姿 -> 速度意图
    |
SafetySupervisor         安全边界：限幅、加速度、看门狗、急停
    |
RobotDevice (Protocol)   设备接口：速度进出、遥测、急停
    |
SimulatedRobot | SerialRobotDevice
                    |
                 TelemetryCodec -> FrameDecoder -> pyserial
```

依赖方向始终向下。业务层不知道串口是否存在，设备层不知道航点是什么。

## 关键不变量

1. `Velocity` 和 `WheelSpeed` 拒绝非有限数值。
2. 所有设备命令必须经过 `SafetySupervisor`。
3. 速度同时受最大线速度/角速度与加速度率限制。
4. 超过 `command_timeout_s` 未刷新命令时，监督器主动发送停车。
5. 急停是锁存状态，必须显式调用 `clear_emergency_stop()`，重新发速度不能解锁。
6. 设备报告故障时，监督器自动锁存急停。
7. 任务环有总时长上限，不依赖外层超时。
8. 仿真物理按固定步长推进，不依赖系统时钟，测试可重复。

## 为什么差速轮模型

“机器人”与“控制不了”不足以证明底盘类型（G1/G2）。差速轮是明确标注的**重建假设**，
不是恢复事实。若真机是机械臂、无人机或全向底盘，需要新增相应运动学与设备实现；
`RobotDevice` 与控制/安全边界可保留。

## 串口接入

`SerialRobotDevice` 把传输与语义分开：

- `hal/framing.py`：长度 + CRC-16/CCITT-FALSE，负责切帧、坏帧统计与重同步。
- `hal/protocol.py`：可替换 codec，负责“字节 <-> 速度/遥测”。
- `hal/serial_device.py`：连接、发送、接收、超时和设备健康统计。

当前的 `PlaceholderJsonCodec` 只用于联调，**不是恢复出的协议**。替换 codec 后，
上层无需修改。

## 尚未验证的事项

- 真实驱动器是否接受本项目的速度单位与符号；
- 串口帧格式、波特率、校验方式；
- 轮径、轮距、编码器方向、IMU 坐标约定；
- 控制周期能否满足真实闭环；
- 硬件急停是否独立于软件链路；
- 真实航点任务与障碍物/碰撞约束。
